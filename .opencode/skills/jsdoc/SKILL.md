# JSDoc

あらゆるケースを網羅した詳細な JSDoc フォーマットガイドです。常に適用すべき基本ルールは `jsdoc` ルールにまとめられています。このガイドは、より詳しい仕様を確認したいときのリファレンスとして利用してください。

## 併用する規範

作業前に `../japanese/SKILL.md` を読んでください。

## `@example` の書き方

### 短い 1 行の例

ラベルは `@example` 行に記述し、コードは次の行にインラインコードとして記述します。

```ts
/**
 * @example 必須パラメーター
 * `name: Type`
 *
 * @example オプションパラメーター
 * `name?: Type`
 */
```

### 複数行の例

`@example` の直後にフェンス付きコードブロックを書きます。

````ts
/**
 * @example
 * ```ts
 * const result = buildParams(node, {
 *   paramsType: "inline",
 * });
 * ```
 */
````

### 複数のパターンを示す場合

それぞれを独立した `@example` ブロックとして記述します。

```ts
/**
 * @example オブジェクト形式
 * `{ id, data, params }: { id: string; data: Data; params?: QueryParams }`
 *
 * @example インライン形式
 * `id: string, data: Data, params?: QueryParams`
 */
```

### ルール

| ルール                    | 正しい例                                   | 誤った例                                      |
| ------------------------- | ------------------------------------------ | --------------------------------------------- |
| ラベル + インラインコード | `@example 必須\nname: Type`                | `@example name: Type`（タグ行にコードを書く） |
| 複数行のコード            | ` ```ts ``` ` のフェンス付きコードブロック | フェンスなしでコードを書く                    |
| 短い例                    | インラインコードを使用                     | トリプルバッククォートを使う（大げさすぎる）  |
| 1つの例につき1つの内容    | `@example` を分けて記述                    | 1つの `@example` にすべて詰め込む             |

## タグ

### よく使うタグ

| タグ          | 用途                   | 補足                                                               |
| ------------- | ---------------------- | ------------------------------------------------------------------ |
| `@default`    | デフォルト値           | デフォルト値が自明でない場合のみ使用します（`undefined` は不要）。 |
| `@example`    | 使用例                 | 複雑な API や複数パターンの API では積極的に使用します。           |
| `@note`       | 注意事項               | バージョン情報や破壊的変更などを記載します。                       |
| `@deprecated` | 非推奨であることを示す | 移行方法もあわせて記載します。                                     |

### 必要な場合のみ使うタグ

| タグ        | 用途                     |
| ----------- | ------------------------ |
| `@see`      | 外部ドキュメントへの参照 |
| `@internal` | 内部 API                 |
| `@beta`     | 実験的な機能             |

### 使用しないタグ（TypeScript がすでに提供しているため）

- `@type`：TypeScript の型注釈を利用します
- `@typedef`：`type` または `interface` を利用します
- `@default undefined`：オプショナル (`?`) であることがすでに `undefined` を意味します

### 使用に留意点のあるタグ

| タグ       | 留意点                 | 正しい例        | 誤った例                            |
| ---------- | ---------------------- | --------------- | ----------------------------------- |
| `@param`   | 型表記とダッシュが不要 | `@param 説明`   | `@param {ArrayBuffer} value - 説明` |
| `@returns` | 型表記とダッシュが不要 | `@returns 説明` | `@returns {string} - 説明`          |

## ドキュメントの書き方

### シンプルなプロパティー

常に複数行の JSDoc を使用します。

```ts
/**
 * 生成されるファイルの出力先ディレクトリーです。
 */
outDir?: string
```

`/** 説明 */` のような 1 行形式は使用せず、必ず複数行で記述してください。

### 自明でないデフォルト値を持つプロパティー

```ts
/**
 * トラバーサル中に同時実行されるコールバックの最大数です。
 *
 * 値を大きくすると I/O バウンドな処理をより並列化でき、小さくするとメモリ使用量を抑えられます。
 *
 * @default 30
 */
concurrency?: number
```

TypeScript の型だけでデフォルト値が明らかな場合（`false` や `undefined` など）は、`@default` を付けないでください。

### 列挙値・ユニオン型

```ts
/**
 * 関数シグネチャでパスパラメータをどのように出力するかを指定します。
 *
 * - `"object"`: 分割代入された単一のオブジェクト引数としてまとめます。
 * - `"inline"`: 各パラメータを個別の引数として展開します。
 * - `"inlineSpread"`: 単一の可変長引数として出力します。
 */
pathParamsType: "object" | "inline" | "inlineSpread";
```

### ネストされたプロパティー

各プロパティごとに、それぞれ独立した複数行 JSDoc を記述します。

```ts
names?: {
  /**
   * リクエストボディ引数の名前です。
   *
   * @default "data"
   */
  data?: string

  /**
   * クエリパラメータをまとめる引数の名前です。
   *
   * @default "params"
   */
  params?: string
}
```

### 関数のドキュメント

シグネチャーだけでは伝わらない情報がある場合にのみ JSDoc を追加します。

```ts
// シグネチャだけで十分に意味が分かるため、JSDoc は不要です。
function camelCase(str: string): string { ... }

// 振る舞いや分かりにくい仕様を説明できるため、JSDoc を付けます。
/**
 * スキーマが通常の文字列として扱われる場合に `true` を返します。
 *
 * - `string`、`uuid`、`email`、`url`、`datetime` は常に通常の文字列です。
 * - `date` と `time` は、`representation` が `'string'` の場合のみ通常の文字列になります。
 */
function isStringType(node: SchemaNode): boolean { ... }
```

### 改行ルール

1文の途中で改行しないでください。

正しい例:

```ts
/**
 * これは本来とても長い文章ですが、途中で改行しません。
 *
 * @param value これは本来とても長い文章ですが、途中で改行しません。
 */
```

誤った例:

```ts
/**
 * これはとても長い文章なので、
 * 句読点などで途中で改行してしまいます。
 *
 * @param value これはとても長い文章なので、
 *              句読点などで途中で改行してしまいます。
 */
```

## ガイドライン

### 推奨

- TypeScript の型ではなく、そのプロパティーや関数の役割を説明します。
- 公開する型・プロパティ・関数には必ず JSDoc を付けます。
- JSDoc は常に複数行で記述します。
- 具体的で完結した文章を書きます。
- `@default` はデフォルト値が自明でない場合のみ付けます。
- 複数の使い方がある場合は `@example` を複数記述します。
- `@example` のラベルは短く分かりやすくします。

### 非推奨

- `/** 説明 */` のような 1 行形式を書きます。
- `@default undefined` を書きます。
- `@example` 行に直接コードを書きます。
- 自明なプロパティーまで過剰に説明します。

## タグの記述順

1. 説明（必須）
2. バリエーションや動作の箇条書き（必要な場合）
3. `@param`（必要な場合）
4. `@default`（デフォルト値が自明でない場合）
5. `@returns`（必要な場合）
6. `@example`（必要に応じて複数）
7. `@note`（必要な場合）
8. `@deprecated`（非推奨の場合）
9. `@see`（関連資料を示す場合）
